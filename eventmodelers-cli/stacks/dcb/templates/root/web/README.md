# web/ — the frontend

A static React app (Vite) next to the backend, built from the same model. Each slice with a screen gets its UI
here (`src/slices/<slice>/`), written by the build loop from the screen's mockup and the backend's
`/openapi.json`.

**Stack:** Vite, React 19, TypeScript, Tailwind CSS v4 + shadcn/ui, React Router, TanStack Query, React Hook Form
+ Zod, openapi-fetch (types from openapi-typescript), Vitest + Testing Library + MSW.

```bash
npm install
npm run gen:api        # types for every backend route, from http://localhost:3000/openapi.json (API_URL=… for another)
npm run dev            # against the backend (VITE_API_BASE in .env; the backend needs CORS_ORIGIN=http://localhost:5173)
npm run dev:mock       # no backend: MSW answers from src/mocks/handlers.ts (the scenario examples)
npm test               # component tests, answered by MSW
npm run build          # static files in dist/ (for S3 + CloudFront)
npm run design-system  # compile the design system into ../snippets/design-system.html for the board
```

| Where | What |
|---|---|
| `src/lib/api.ts` | the only code that calls the backend: `api` (typed), `command`, `read`, `afterWrite` |
| `src/lib/api-types.ts` | generated by `gen:api`; never edit |
| `src/mocks/handlers.ts` | mock responses, one set per slice, from its scenarios |
| `src/routes.tsx` | every page; one page per screen title |
| `src/slices/<slice>/` | a slice's components (a form per command, a view per read model) |
| `src/components/ui/` | shadcn/ui components (`npx shadcn@latest add <name>` adds more) |
| `src/styles/design-system.css` | the design system: tokens, and the `mock-*` classes mockups use |

**Read-your-writes.** A command returns the event store position it reached (`command(...).position`, from the
`ETag`). Only an **async** (`database-projected`) read model can still be behind it. To read your own write from
one, pass `headers: afterWrite(position)`, and the backend waits until the read model has caught up. Inline and
live read models are already current when the command returns: read them without it.

**One look on the board and in the app.** Mockups on prooph board import the `design-system` snippet.
`npm run design-system` compiles `src/styles/design-system.css` into that snippet. It includes every Tailwind
class used in `web/` or in any mockup in `../workspace.json`, plus `src/styles/board.css`. Run it after changing
the design system or adding classes to a mockup, then `emcli sync push`. It replaces the snippet, including an
`emcli snippet add --starter` one.
